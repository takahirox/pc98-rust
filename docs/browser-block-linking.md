# Event-bounded RAM linking and partial scanout — Issue #172

This continues the [throughput comparison](browser-block-parity.md) and
[calibrated playback investigation](cpu-budget-evaluation.md). The browser core
links ready RAM traces within one device-event budget and retains unchanged
scanlines in the render Worker. The interpreter, guest clocks, PCM synthesis,
audio reserve and display settings remain authoritative.

## Results

Three fresh fixed-work pairs reduce median active time from **2,180.0 to
1,969.8 ms (9.64%)**. Every pair improves by 9.23–10.60%, advances exactly
24.0002795 guest seconds, and matches CPU/time, conventional RAM, frame and PCM
at setup and 8/16/24 guest seconds. The actual snapshot-render export also
matches the independent full-frame output at every checkpoint.

| Rust completion calls in the measured window | 15,143,698 | 5,252,498 |
| Direct instructions in that window | 106,054,200 | 106,200,490 |

| Generated bytes | 5,408,439 | 5,798,351 |

The call reduction is **65.32%**. Generated bytes grow 7.21%; they are totals,
not resident-memory measurements. Setup active time falls from a median
10,198.2 to 9,609.1 ms; it excludes asynchronous compiler waits and does not
establish a corresponding cold wall-time improvement.

Three fresh stationary controls take 1,165.8–1,194.1 ms, median **1,180.9 ms**
for 24 guest seconds. Pinned NP2kai takes 1,697.6–1,936.8 ms, median
**1,721.0 ms** for 24.014471442 guest seconds. Normalized host time per guest
second gives a selected/reference ratio of **0.687**, within the previous 1.05
criterion. A single 0.5-CPU cross-check gives 6,652.2 versus 10,469.5 ms
(ratio 0.636), but its calibration differs between engines; it is exploratory.
The three-run unrestricted comparison is the primary reference result.

Two fresh production runs per variant use the updated Sharp CRT default, with
active filtering and no GPU fallback in every measured window. All unrestricted
windows retain about 60 fps, guest/wall about 1.0 and zero missing PCM. At a
shared 0.5-CPU quota, the following are medians of two runs:

Missing-frame medians fall 11.45% and 11.23%, but guest progress improves only
slightly. First-window progress ranges overlap, so these samples do not establish
a uniform production speedup. Baseline Worker calibration ranges from 3.62 to
4.14 times its unrestricted control, while the selected runs range from 2.04 to
3.91. Requested/configured/observed quotas match; the synthetic slowdown is not
assumed to be a constant multiplier or used to normalize away the deficit.
Callback progress is only 0.69–0.74 of wall time in these strict controls.
All overflow, drop, sequence, checksum and emulator error counts remain zero.

**Audio starvation remains.** These window names describe the intended input
schedule: every constrained second window has zero HDD reads, versus 57 when
unrestricted. The constrained runs therefore do not reach the same later scene.
The fixed-work comparison above supplies the independent equivalence result.
No real-time NP2 audio-parity or dropout-free older-PC claim follows from these
measurements. The [sanitized numeric report](browser-block-linking-results.json)
retains every sample, calibration and runtime identity.

## Sources and retained design

[NP2kai's event scheduler](https://github.com/AZO234/NP2kai/blob/5939e0c6d5985c4c08fc70f289a83290e5d3e6f7/nevent.c)
and [text/graphics update tracking](https://github.com/AZO234/NP2kai/blob/5939e0c6d5985c4c08fc70f289a83290e5d3e6f7/vram/maketgrp.c)
provide relevant PC-98 examples: CPU execution is bounded by events, and text/VRAM
updates contribute to line renewal. [QEMU's chaining documentation](https://www.qemu.org/docs/master/devel/tcg.html#direct-block-chaining)
explains avoiding repeated returns to the main dispatch loop while retaining exits
for state changes that could expose interrupts. These are design references;
no upstream instruction or renderer implementation is copied.

The new Wasm dispatcher looks up the next ready trace by full CS-base/IP key and
plan identity. Rust validates the first entry and establishes the earliest device
or slice deadline. Generated entries check current IP, CS and original code bytes
before effects; every trace uses its own code hull for write guards. The run ends
on a missing link, guard failure, work cap or event budget, and Rust retires the
accumulated clocks and final instruction's timing once. A zero-progress exit
cannot loop. Unsupported operations and state changes return to normal dispatch.
All six segment descriptors must be ordinary before linking is enabled. Cache
slot replacement, invalidation, unregistration and reset remove stale links.

The renderer compares exact scanout inputs against its retained snapshot. With
stable mode, GDCs, palettes, glyphs and blink phase, only rows whose visible text
or graphics inputs differ are rasterized. Comparisons handle text partitions,
40-column scanout, planar page/address wraps, doubled rows and PEGC pitch/wraps.
Other changes retain full rasterization. The complete snapshot and RGBA transport,
frame credits, scanout clocks and raw capture behavior stay unchanged. No guest
write-notification machinery is added to the CPU hot path.

The link table reserves 192 KiB and the completion context grows by 12 bytes.
Generated-code and core sizes are recorded in the numeric results. These counts
are not measurements of browser resident memory. No native executable-memory JIT,
mandatory shared-memory threads or new Wasm feature is introduced.

## Diagnosis and rejected trials

A separate current-main emulator-Worker profile collected 15,994 samples, of which
14,203 were idle. RAM entry preparation, dispatch, completion and exported entry
accounted for 126, 110, 63 and 24 self samples. These identify recurring boundary
work; they do not measure the CPU shares of the renderer, AudioWorklet or browser
compiler threads. Production phase timings are elapsed times that include quota
stalls and may overlap other Workers. Asynchronous compilation latency is never
reported as compiler CPU time.

| Selection trial | Observation | Decision |
| --- | --- | --- |
| Raise heat threshold from 32 to 128 | Fewer compilations; no established audio gain; actual slowdown differs | Remove |
| Batch native-rate worklet copies | First-window gain, no sustained second-window gain | Remove |
| Separate compiler Worker | Shared CPU quota still starves production | Remove |
| Link traces alone | Fixed-work gain; constrained audio does not improve | Retain for measured CPU work reduction, combine with scanout work |
| Link plus partial scanout | Lower raster elapsed time and missing PCM in the Original-pixels selection run | Select for the fresh controls above |
| Compile small modules synchronously | More translated execution, no established audio gain | Remove |

Selection runs are single samples with different measured slowdown and scene
progress. Their timing differences are not isolated causal effects. None of the
rejected implementation, altered thresholds or worklet changes remains.

## Measurement scope

All timed controls run serially without builds, tests or profilers. Raw media,
profiles, guest state/code, PCM and captures remain outside Git. The linked
numeric report contains only sanitized measurements and executable identities.

During this work main advanced to `2f6878c`, which defaults fresh sessions to
Sharp CRT. Retained production comparisons use that same updated UI and default
in both controls. Earlier selection runs used `34aa79b` and Original pixels;
their results are separate and do not establish a causal CRT-versus-off effect.
Display activity and fallback are recorded alongside the frozen source hashes.

The [CPU-budget workflow](cpu-budget-evaluation.md) uses network-isolated owned
containers, a 4 ms quota period and the cached immutable Playwright image. Both
Dedicated Workers are independently calibrated. A quota is not a uniform CPU
slowdown or an old CPU/cache/GPU simulation. Calibration differences, scene
progress, callback progress and all failing rows must remain visible. Headless
audio counters do not establish physical-device output quality.

Fixed-work pairs compare CPU/time, conventional RAM, frame and PCM at setup and
8/16/24 guest seconds. Their active time excludes asynchronous compilation waits
and checkpoint hashing. Stationary reference controls include CPU and software
rasterization; they have separate cold setup measurements. The pinned NP2kai
configuration and model differences are unchanged from the previous comparison.
The reference has no production AudioWorklet counterpart in this harness, so a
stationary ratio cannot establish real-time audio equivalence or universal speed.

## Validation

Validation includes 654 native tests with debug assertions/overflow checks,
59 final library checks and seven focused snapshot tests after fixture refinements,
38 actual optimized release-Wasm tests, 56 Node tests, all-target/all-feature
Clippy, formatting, 56 legal fixture/preparation steps plus 13 offline fetch tests,
and the 32-asset publication audit. The final measured core is the normal build,
SHA-256 `9fa97ec12b42539872bd860f33f418c05f82614f4e59d13abed040b0bbca92d7`.

Stock Chrome 157 completed all 140 local guest assertions, but its host Node 26
runner stalled before starting the Pages project and was interrupted. A cached
Node 22/Chrome 141 container passed both serial audio cases. Four-way browser
acceptance then exceeded its 4 GiB container limit (three OOM kills); the affected
local FDC/HDD cases passed all six serial checks, and the complete Pages rerun
passed 135 with five intentional skips at two workers, with no OOM events.
After importing the Sharp-default update, both serial audio cases and all 32
presentation checks passed again with one worker. The final-revision complete
CI acceptance and review are recorded in the implementation PR. No assertion,
timeout or audio-continuity threshold is weakened.

New coverage exercises linked work/event exits, writes to a subsequent trace,
nonempty-map reset, slot reuse, unregistration and unusual unused segments.
Scanout cases cover VM/Ap, 40 columns, wide text partitions, planar and PEGC wraps,
doubled rows, hidden writes and blink changes. A BIOS fixture also now expects
the actual intermediate AH=04 state when an event cuts after MOV AH,04; exact
CPU/time/RAM/frame/PCM comparisons remain in force.

Required post-merge verification: None. The broader low-CPU audio problem remains
tracked by #146; residual missing PCM is not hidden by increasing buffers,
changing guest speed or weakening continuity assertions.
