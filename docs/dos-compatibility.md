# DOS compatibility: tested subsets and limits

Issue #11 adds DOS device workflows to the CPU work merged by PR #10.
See the [current Ap device contracts, fixtures and acceptance evidence](ap-devices.md).
Physical hardware fidelity remains bounded by the documented unsupported subsets.
Historical PR #8/#10 validation records below describe their earlier checkpoints.

The existing PR #8 baseline is preserved: Two independently authored native
PC-98 DOS applications now execute their actual x86 code under the pinned guest
FreeDOS kernel and FreeCOM: ADV98's Japanese adventure sample and 98VIDEOP. There
is no application-name recognition, host INT 21h implementation, host font
rasterization, host game logic, or substitution of application graphics.

## Reproduce and use

```sh
python3 tools/prepare_freedos.py
python3 tools/prepare_dos_apps.py
python3 tools/prepare_cpu_fixture.py
python3 tools/prepare_hdd_fixture.py
python3 tools/prepare_music_fixture.py
python3 tools/prepare_device_fixture.py
python3 tools/build_font.py --check
cargo test --locked
cargo clippy --all-targets -- -D warnings
cargo fmt --check
npm ci
npx playwright install chromium
npm test
```

The DOS-app preparation command checks all downloads and generated images against
[the checked-in manifest](../fixtures/dos-apps-manifest.json). It deliberately
fails for a stale/different fixture. It also retains complete corresponding GPL
DOS sources beside the FreeDOS image. Source archives are read by exact member
name, never unpacked onto the host by the preparation script. Download size is
capped at 8 MiB per archive; inserted floppies retain the existing 4 MiB limit.

In the browser select **PC-9821Ap DOS · experimental**, then insert one of
`fixtures/dos-apps/{adv98,98videop,fm98}.hdm` in drive 1. These disks auto-run their
application through FreeCOM. In ADV98 press Return to start, Return to advance
Japanese dialogue, and arrows/Return to choose Look, Talk or Move. Talk progresses
the sample's branching story. Esc opens the system menu; Return selects Save and
then slot 1. Export the disk to keep `SAVE1.DAT`; reinsert it and choose Load on
the title screen. The source scenario is a small playable ADV sample, not a
complete commercial-length game. The original `adv98.hdm` is silent without a
driver. The new `music.hdm` includes
a published guest PMD driver and original compiled score, started by the unchanged
game; see [device instructions](ap-devices.md). Enable sound and insert
`fm98.hdm` to hear its independent
FM routines in the separate DOS test. These are distinct compatibility claims.

Headless uses the same core, with an explicit profile:

```sh
cargo run --bin headless -- fixtures/dos-apps/adv98.hdm 16000000 --ap
```

Neither the GPL DOS images nor application archives are copied into `web/` or
published by Pages. Browser tests upload local fixture bytes through the same
file input users use. Publication still contains the two existing MIT demo disks,
the compiled core and notices, including the Shinonome license/authors.

## Ap DOS profile boundaries

The physical baseline is the official
[NEC PC-9821Ap/U2 specification](https://support.nec-lavie.jp/support/product/data/spec/cpu/b211-1.html):
i486DX2 66 MHz, standard 3.6 MB RAM, 512 KB graphics VRAM, two floppies and
16/256-color graphics. The configuration here is a **bounded DOS subset**, not a
complete reproduction of those specifications.

| Area | Implemented and tested | Remaining limits |
| --- | --- | --- |
| CPU | Original shared 8/16/32-bit real-mode interpreter; 66/67 overrides, EAX–EDI, FS/GS, ModR/M/SIB, dword ALU/stack/strings/control flow/I/O, selected 386/486 integer 0F instructions, EFLAGS AC, restartable #DE/#BR/#UD/#SS/#GP and #DB traps. Real-mode LGDT/SGDT and LIDT/SIDT provide the [GDTR](hardware.md#ap-real-mode-gdtr) and [IDTR prerequisites](hardware.md#ap-real-mode-idtr); Ap supports relocated real-mode vectors, table-limit exception 8 and bounded shutdown when that entry is unavailable. Ap retains masked shift counts and encoded AAM/AAD radix; V30 behavior remains selected by VM | No protected mode, unreal mode, paging, DPMI, FPU, CPUID, other system/control/debug-register instructions or complete 486 ISA/timing. Explicit invalid encodings fault; valid unimplemented instructions stop with a diagnostic. See CPU coverage below |
| RAM | 640 KiB conventional plus 3 MiB at physical 100000–3FFFFF; BWA 401h reports 24 × 128 KiB; holes and firmware retain PC-98 mapping | HMA is reachable with A20 enabled, including dword accesses. Address override does not enlarge the real-mode 64 KiB segment limit, and INT 1F/90 now provides validated byte copies to extended RAM. XMS/EMS managers remain absent; selected guests need conventional RAM and/or this BIOS service |
| A20 | PC-98 F2 write enables A20; F6=02/03 enables/disables; F2/F6 read bit 0 reports masked state; reset masks it | No IBM port 92 or AT keyboard-controller gate. F0 remains the private synthetic-firmware trap, not an emulated CPU reset port |
| Bitmap | Two four-plane 128 KiB pages; B/R/G at A8000/B0000/B8000, intensity at E0000; independent CPU/display pages; analog palette 16 × 12-bit RGB; four-plane GRCG TDW/RMW/TCR | Aligned EGC raster operations and 512 KiB PEGC packed 256-color storage/windows/palette are now tested by independent DEBUG; see the device audit. No arbitrary EGC shifts, PEGC planar mode, 480-line mode or GDC vector engine |
| Text/CG | Shinonome JIS X 0208 16×16 glyphs; A1/A3 glyph selection, A5 half/line, A9 data, A4000 CG window in dot access mode; text VRAM low byte JIS row minus 20h, high byte cell, right-half flag; text color independent of bitmap analog palette | CG window implements the selected 32-byte ordinary glyph, mirrored across the decoded window. [Ap BIOS user characters](user-characters.md) now share mutable RAM across text, CG and full-width BIOS reads. No NEC extended glyphs, FEP or full Japanese ANK/kana coverage; ANK still uses the original simplified Latin font |
| Display IRQ | Port 64 arms one IRQ2 at the next scheduled vertical frame; guest rearming required | Fixed 133333 scheduling clocks/frame, not authentic Ap raster frequencies or cycle accuracy |
| Sound | Original 26K-compatible OPN subset, three four-operator FM voices, key-on/off, algorithm/feedback, pitch/TL and approximate envelopes; SSG tone/noise/envelope; busy flag and timers A/B, slave IRQ4 | Not full YM2203 fidelity: no prescaler changes, channel-3 special mode, exact detune/rate scaling or SSG-EG operator envelopes. OPNA extended FM bank and 86 playback FIFO now exist; 98VIDEOP uses PCM and ADV98 starts guest PMD FM/SSG music in `music.hdm`. Rhythm, ADPCM, recording and sound ROM remain absent |
| Storage/input | Existing raw/D88 floppy validation, FDC/DMA, PC-98 BIOS, keyboard; guest DOS FAT files survive export/reimport | IDE HDI boot/persistence, bus mouse ports and original guest INT 33 driver are now tested with unchanged ADV98. No additional floppy format, DOS extender or Windows support |
| Timing/browser | Same core native/Wasm, 8 MHz deterministic scheduler, bounded REP/step/audio queues, explicit profile selector and reset preserving mounted disks | 66 MHz is not simulated; this is not a performance/cycle reproduction of the physical Ap |

Port/map facts were checked against independent hardware documentation:
[display/CG/GRCG](https://www.webtech.co.jp/company/doc/undocumented_mem/io_disp.txt),
[CPU/A20](https://www.webtech.co.jp/company/doc/undocumented_mem/io_cpu.txt),
[BIOS work areas](https://www.webtech.co.jp/company/doc/undocumented_mem/memsys.txt),
[sound I/O](https://www.webtech.co.jp/company/doc/undocumented_mem/io_sound.txt),
and Yamaha's YM2203 datasheet. Sound synthesis is newly written mathematical
operator/phase/envelope code; no emulation library, implementation or chip table
was consulted/copied. The sine calculation and envelopes are approximations,
not measured chip output. The existing VM profile retains its original map,
three planes, Latin font, beeper and V30 behavior.

## Issue #9 CPU coverage and independent guest evidence

The shared decoder now applies operand and address overrides independently. Repeated
66/67 prefixes select an override rather than toggling it. Register byte/word writes
preserve upper words; dword writes replace all 32 bits. ModR/M/SIB handles scaled
indices, no-base/disp32, signed displacements and default SS for EBP/ESP bases.
FS/GS overrides, MOV segment, PUSH/POP FS/GS and LSS/LFS/LGS are available on Ap.

Common instructions now support dword ALU/TEST, INC/DEC, shifts/rotates, signed and
unsigned multiply/divide, MOV/XCHG, LEA, stack/PUSHAD/POPAD/ENTER/LEAVE, immediate
and indirect near/far transfers, IRETD, PUSHFD/POPFD, CBW/CWDE/CWD/CDQ, strings
and I/O. REP uses the address size for ECX/ESI/EDI and retires at most one element
per scheduler slot. Added 0F forms include near Jcc, SETcc, MOVZX/MOVSX, IMUL,
BSF/BSR, BT/BTS/BTR/BTC, SHLD/SHRD, CMPXCHG/XADD and 32-bit BSWAP. BOUND is
implemented for Ap. CPULEVEL's ID-flag probe fails as expected for an early DX2;
its AC-flag probe succeeds. This does not advertise a working FPU or CPUID.

Ap memory operands and instruction fetches respect the real-mode 64 KiB segment
limit, including multi-byte accesses at FFFF and overlong instructions. #DE, #BR,
invalid encodings, #SS and #GP save the first prefix address in the 16-bit real-mode
IVT frame. Faulting writes are checked before modifying any bytes; compound stack
writes preflight every element. Register state is restored before fault delivery.
Single-step traps save the next instruction address; SS-load and STI shadows are
distinct. Real-mode INT/INT3/INTO, IRQs and exceptions always save a six-byte
FLAGS/CS/IP frame, regardless of a 66 prefix, and clear IF, TF and AC on entry.
Ordinary IRET consumes this word frame; IRETD consumes a software-constructed
three-dword frame and can restore AC. A broken exception stack produces a bounded
diagnostic; double/triple-fault reset behavior is not implemented. VM retains
wrapped offsets and its existing V30 bit/flags/radix behavior.

Instruction behavior was implemented from architectural documentation, including
[Intel's instruction/system manuals](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html),
and the [original 80386 instruction reference, hosted by Stanford](https://www.scs.stanford.edu/05au-cs240c/lab/i386/c17.htm),
without consulting or copying an emulator implementation. These are functional
semantics, not a physical 66 MHz timing model.

[CPULEVEL provenance](../fixtures/cpu-manifest.json) pins Eric Auer's independent
2004–2008 public-domain CPU diagnostic, its complete original archive and each
selected source/binary hash. `prepare_cpu_fixture.py` assembles its unmodified
NASM source and includes that source on `cpu386.hdm`, alongside the same pinned
FreeDOS/FreeCOM used by existing tests. The downloaded archive is retained with
the disk and DOS sources/notices. No new guest is published by Pages.

Native `tests/cpu386.rs` exercises instruction/flag/address/fault edges and boots
this disk through the actual kernel and shell. CPULEVEL executes 26 operand-size
overrides and returns DOS errorlevel 4; the guest batch prints `CPULEVEL 486 VERIFIED`.
The test also requires the diagnostic's `i486 or compatible` and negative CPUID
messages. Browser `dos-apps.spec.js` repeats this on real release Wasm at both
root and Pages paths, including reset/re-execution. This is a portable third-party
DOS utility, **not** a new game, musical fixture or a substitute for the remaining
HDD/mouse/256-color/game-audio acceptance.
