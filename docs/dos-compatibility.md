# Issue #7: independent DOS compatibility slice

This is a **partial implementation of Issue #7**, not a claim of broad PC-9821
compatibility or grounds to close the Issue. Two independently authored native
PC-98 DOS applications now execute their actual x86 code under the pinned guest
FreeDOS kernel and FreeCOM: ADV98's Japanese adventure sample and 98VIDEOP. There
is no application-name recognition, host INT 21h implementation, host font
rasterization, host game logic, or substitution of application graphics.

## Reproduce and use

```sh
python3 tools/prepare_freedos.py
python3 tools/prepare_dos_apps.py
python3 tools/build_font.py --check
cargo test --locked
cargo clippy --all-targets -- -D warnings
cargo fmt --check
npm ci
npx playwright install chromium
npm test
```

The DOS-app preparation command checks all downloads and generated images against
[the checked-in manifest](../fixtures/dos-apps-manifest.json). It deliberately
fails for a stale/different fixture. It also retains complete corresponding GPL
DOS sources beside the FreeDOS image. Source archives are read by exact member
name, never unpacked onto the host by the preparation script. Download size is
capped at 8 MiB per archive; inserted floppies retain the existing 4 MiB limit.

In the browser select **PC-9821Ap DOS · experimental**, then insert one of
`fixtures/dos-apps/{adv98,98videop,fm98}.hdm` in drive 1. These disks auto-run their
application through FreeCOM. In ADV98 press Return to start, Return to advance
Japanese dialogue, and arrows/Return to choose Look, Talk or Move. Talk progresses
the sample's branching story. Esc opens the system menu; Return selects Save and
then slot 1. Export the disk to keep `SAVE1.DAT`; reinsert it and choose Load on
the title screen. The source scenario is a small playable ADV sample, not a
complete commercial-length game. The unmodified released game is silent without
its optional PMD driver. Enable sound and insert `fm98.hdm` to hear its independent
FM routines in the separate DOS test. These are distinct compatibility claims.

Headless uses the same core, with an explicit profile:

```sh
cargo run --bin headless -- fixtures/dos-apps/adv98.hdm 16000000 --ap
```

Neither the GPL DOS images nor application archives are copied into `web/` or
published by Pages. Browser tests upload local fixture bytes through the same
file input users use. Publication still contains the two existing MIT demo disks,
the compiled core and notices, including the Shinonome license/authors.

## Ap DOS profile boundaries

The physical baseline is the official
[NEC PC-9821Ap/U2 specification](https://support.nec-lavie.jp/support/product/data/spec/cpu/b211-1.html):
i486DX2 66 MHz, standard 3.6 MB RAM, 512 KB graphics VRAM, two floppies and
16/256-color graphics. The configuration here is a **bounded DOS subset**, not a
complete reproduction of those specifications.

| Area | Implemented and tested | Remaining limits |
| --- | --- | --- |
| CPU | Existing original 8/16-bit common real-mode interpreter; Ap uses masked shift counts, encoded AAM/AAD radix, 486-style 16-bit FLAGS reserved bits; rejects V30 0F extensions | No 66/67 prefixes, 32-bit registers/addressing, full 386/486 ISA, FPU, protected mode or DPMI; accepted guests use the common 16-bit instructions. Segment accesses still wrap offsets like the VM core, without 286+ segment-limit exceptions |
| RAM | 640 KiB conventional plus 3 MiB at physical 100000–3FFFFF; BWA 401h reports 24 × 128 KiB; holes and firmware retain PC-98 mapping | RAM beyond HMA is not reachable through this interpreter's 16-bit real-mode addresses; no XMS, EMS or INT 1F copy implementation. Accepted guests do not request them |
| A20 | PC-98 F2 write enables A20; F6=02/03 enables/disables; F2/F6 read bit 0 reports masked state; reset masks it | No IBM port 92 or AT keyboard-controller gate. F0 remains the private synthetic-firmware trap, not an emulated CPU reset port |
| Bitmap | Two four-plane 128 KiB pages; B/R/G at A8000/B0000/B8000, intensity at E0000; independent CPU/display pages; analog palette 16 × 12-bit RGB; four-plane GRCG TDW/RMW/TCR | Only 256 KiB of the real machine's 512 KiB graphics storage is exposed; no EGC, PEGC/256-color, 480-line mode or GDC vector engine. None is exercised by these guests |
| Text/CG | Shinonome JIS X 0208 16×16 glyphs; A1/A3 glyph selection, A5 half/line, A9 data, A4000 CG window in dot access mode; text VRAM low byte JIS row minus 20h, high byte cell, right-half flag; text color independent of bitmap analog palette | CG window implements the selected 32-byte ordinary glyph, mirrored across the decoded window. No user-defined fonts, NEC extended glyphs, FEP or full Japanese ANK/kana coverage; ANK still uses the original simplified Latin font |
| Display IRQ | Port 64 arms one IRQ2 at the next scheduled vertical frame; guest rearming required | Fixed 133333 scheduling clocks/frame, not authentic Ap raster frequencies or cycle accuracy |
| Sound | Original 26K-compatible OPN subset, three four-operator FM voices, key-on/off, algorithm/feedback, pitch/TL and approximate envelopes; SSG tone/noise/envelope; busy flag and timers A/B, slave IRQ4 | Not full YM2203 fidelity: no prescaler changes, channel-3 special mode, exact detune/rate scaling or SSG-EG operator envelopes. No OPNA bank, rhythm, ADPCM, 86 PCM FIFO or sound ROM. FM test needs only channel 0, algorithm 7 |
| Storage/input | Existing raw/D88 floppy validation, FDC/DMA, PC-98 BIOS, keyboard; guest DOS FAT files survive export/reimport | No HDD controller/boot, mouse ports/driver, additional floppy format extension, DOS extender or Windows support |
| Timing/browser | Same core native/Wasm, 8 MHz deterministic scheduler, bounded REP/step/audio queues, explicit profile selector and reset preserving mounted disks | 66 MHz is not simulated; this is not a performance/cycle reproduction of the physical Ap |

Port/map facts were checked against independent hardware documentation:
[display/CG/GRCG](https://www.webtech.co.jp/company/doc/undocumented_mem/io_disp.txt),
[CPU/A20](https://www.webtech.co.jp/company/doc/undocumented_mem/io_cpu.txt),
[BIOS work areas](https://www.webtech.co.jp/company/doc/undocumented_mem/memsys.txt),
[sound I/O](https://www.webtech.co.jp/company/doc/undocumented_mem/io_sound.txt),
and Yamaha's YM2203 datasheet. Sound synthesis is newly written mathematical
operator/phase/envelope code; no emulation library, implementation or chip table
was consulted/copied. The sine calculation and envelopes are approximations,
not measured chip output. The existing VM profile retains its original map,
three planes, Latin font, beeper and V30 behavior.

## Acceptance evidence and remaining work

Native `tests/ap.rs` covers exact Japanese glyph pixels from guest CG reads,
all sixteen guest-decoded background indices, keyboard story interaction,
FAT save creation, disk export/reimport and guest load, independent video playback
returning to FreeCOM, guest FM PCM without BEEP, memory/A20/page/ROM boundaries,
Japanese text-VRAM halves, CPU profile differences, and deterministic FM pitch,
timers/busy/IRQ/release. Browser `dos-apps.spec.js` repeats DOS execution,
Japanese glyph comparison, color/input/save/reload, video and FM Web Audio through
the actual release Wasm at both `/` and `/pc98-rust/`. It uses bounded core slices,
not a mocked core. Existing Star Trail, HelloWorld, FreeDOS and Pages tests remain
required. Results for this checkpoint are recorded below after validation.

The end-to-end DOS-game vertical slice is now reproducible, but Issue #7 remains
open: broaden the CPU to genuine 386/486 operand/address behavior and exceptions,
complete the Ap RAM/BIOS and necessary extended-memory interfaces, add bootable
HDD support, and continue guest-first coverage for EGC/PEGC, Japanese ANK/CG,
mouse and OPNA/PCM. The released ADV98 game remains silent without PMD; game-driven
music still needs a license-cleared driver/music path or a different independent
game. The approximate OPN implementation and wrapped-routine audio test do not
establish broad game sound compatibility. No human sign-off, proprietary media,
live Pages URL or post-merge action is required to continue or test this work.
